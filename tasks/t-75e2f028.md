## Description

New upstream 1.3.4 feature (Label, LabelAssignmentResult, PUT/DELETE label routes, labelId(s) filters). Depends on P1 regen. UI: sidebar section + row chips + context menu; consult design/ tier first.

## Plan

See the Artifacts section and the decisions note "Herald Label Caching and UI Architecture" for the shipped design. Summary: v1 embeds no labels on message/conversation/change payloads (that is /api/v2 only, and a v1-consented token is rejected there), so membership is derived from the labelId filter by a per-label sweep on its own 120s cadence; assignments are cached as join rows keyed by (account, label, message) with a denormalized threadID; chips on rows and the reading pane; a sidebar Labels section that lists across folders; optimistic assign/remove reconciled from LabelAssignmentResult.labels.
