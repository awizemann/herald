# Journal-sync audit fix list (commit c78f421) — apply all, each with a discriminating test

1. **Optimistic state vs journal upsert (HIGH).** Add a pending-mutation set to `MailStore` (messageID → the optimistic fields + a token) recorded by `applyLocalAction` and cleared by MailActionService on completion. `upsertMessages` must NOT overwrite pending fields (readAt/starredAt/folder) for a message with a pending mutation — merge: keep the optimistic values, accept everything else. On POST success, `MailActionService` applies the summary the API returned (currently discarded) as authoritative and clears the pending entry. On POST failure, revert ONLY if the row still equals the optimistic snapshot (compare the mutated fields); otherwise clear pending and leave the row (the journal already gave a newer truth). Tests: an older journal upsert during an in-flight star does not un-star (fails today); revert after a failed POST does not undo a journal change applied meanwhile; the existing `equalEchoedUpsertIsANoOp` keeps its equal-echo half but drop/rewrite the "differing echo must update" half so it doesn't assert the bug (a differing echo for a NON-pending row still updates — that part is fine, make it explicit).
2. **Per-page conversation refresh (HIGH).** In `consumeChanges`, refresh touched conversation scopes for THAT page before persisting that page's cursor (or persist a dirty-scope set in `CachedSyncCheckpoint` and drain it first thing next `consumeChanges`; pick the simpler — per-page refresh is fine, scopes are few). Test: throw on page 3 → scopes touched by pages 1–2 were refreshed (assert `api.conversationScopes()`), cursor at page 2.
3. **Folder-move source scope (HIGH).** `upsertMessages` returns previous (mailboxKey, folder) per changed id (or `apply` reads existing first); when an upsert changes folder, add BOTH old and new scopes to `touched`. Test: journal upsert inbox→archived refreshes inbox AND archived scopes (fails today).
4. **New-mailbox bootstrap atomicity (HIGH).** Do not persist a new mailbox's `CachedMailbox` row until its listing completes: upsert already-known mailboxes first; for each NEW mailbox: list (messages + conversations) → then upsert the mailbox row. Test: listing throws → mailbox row absent → next pass bootstraps it (fails today).
5. **stop() must be awaitable; passes must not outlive stop (MEDIUM).** Add `func stopAndWait() async` (cancel + await loopTask); `AppEnvironment.teardownGraph`/account switch use it before `deleteAll`; guard `runPass` with a generation counter captured at pass start — a pass whose generation != current drops its results (no store writes after stop). Test: gate the fake mid-page, call `stopAndWait()` then `deleteAll`; assert no rows/checkpoint appear afterwards.
6. **404 detection only on the cursor-less probe (MEDIUM).** A 404 on `/changes` WITH a cursor is a pass failure (backoff), not "unsupported"; only the probe (cursor nil) flips `legacyAccounts`. Test: 404 on a cursored page keeps journal mode and reports `.failed`.
7. Process a change page in journal order (don't partition upserts then deletes). Test: [upsert m1, delete m1] leaves m1 absent; [delete m1, upsert m1] leaves it present.
