## Description

From documents/reports/full-surface-audit-2026-09-04.md (perf §): sweep aggressive only when label UI visible (10-15min otherwise; skip replaceAssignments when unchanged); conversations(withLabel:)/labelIDsByThread propertiesToFetch/batching; precompute per-label counts + Set-based per-thread index in reloadLabelIndex; drop redundant reloadLabelIndex in setLabel label-listing path.

## Plan

Landed 2026-09-04, branch feat/upstream-134-adoption.

1. Cadence gating — `SyncEngine.setLabelSurfaceVisible(_:)` + `defaultIdleLabelPollInterval` (750s), ctor-clamped to `max(idle, visible)`. Signal driven from `MailViewModel.updateLabelSurfaceVisibility()`: `selectedLabelID != nil || (!labels.isEmpty && isAppActive)`, pushed only on a flip, from `reloadLabels` / `setActive` / `showLabel`. `refreshLabelsNow()` unchanged as the immediate path.
2. Unchanged-sweep skip — per-label `SweepDigest(count, Set(rows).hashValue)` in the engine; order-independent, count-carrying, dropped by `start()` and by `refreshLabelsNow()`, pruned to live labels, never recorded for a page-capped walk.
3. Store fetch tuning — new `MailStore.labelIndex(accountID:)` (propertiesToFetch + `enumerate(batchSize: 500)`) returning index + resolved counts in one pass; `conversations(withLabel:)` now filters thread ids in the store via chunked `Array.contains` predicates (500/chunk), per-chunk distinct-thread early stop, `sortDate` merge sort only when multi-chunk.
4. Badge precompute — `labelThreadCounts` on the view-model, `threadCount(forLabel:)` is a dictionary lookup; `labelIDsByThread` is now `[String: Set<String>]`. Per the A1 comment the count is intersected against cached conversation thread ids, so badge == listing.
5. setLabel dedup — `reloadIndexAfterLabelChange()` does the either/or, replacing the index-reload-then-conversations-reload double read.
