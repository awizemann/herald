## Description

AppEnvironment.restoreAccounts and AuthCoordinator read SecItem synchronously on main. Route via Task.detached or make AuthCoordinator an actor.

DONE 2026-09-05 (branch fix/signin-hang-recovery, alongside Herald #9 / t-a3dbe1a1). Both paths covered: AuthCoordinator now runs every AccountStore call in the auth path off the main actor via a private `offMain` (Task.detached, userInitiated) — clientID read + setClientID, add + setTokens, remove, and the revocation token read — and the boot path uses the new async `AuthCoordinator.loadAccounts()` from `AppEnvironment.restoreAccounts`. The store itself was deliberately NOT rewritten: `AccountStore` is a synchronous nonisolated protocol behind os_unfair_lock (see "Herald Concurrency Rules"), so the fix belongs at the call sites. Note the honest limit, recorded in code comments and in the memory note: a blocked SecItem call cannot be interrupted, so cancellation does not shorten it — what this buys is a responsive, cancellable main actor. Regression test: HeraldTests/SignInRecoveryTests "a blocking Keychain read stalls off the main actor, which stays free".

Nothing remains.
