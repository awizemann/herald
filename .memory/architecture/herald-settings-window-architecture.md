Redesign phase R7 (task t-e07965ec, commit eac3897). Settings is a two-column window (handoff §3.2): a drill-down source list beside a detail pane. Root pages General/Notifications/Privacy/Account/Signatures are built; R8 (below) built the domain pages Overview/Mailboxes/Signatures. Remove domain stays a placeholder for R9.

## Observations
- [decision] Scene: `NavigationSplitView` inside the `Settings` scene, sidebar pinned at 240 (`.navigationSplitViewColumnWidth`) with `.toolbar(removing: .sidebarToggle)` on the SIDEBAR column, `.toolbar(removing: .title)` + `.toolbarBackgroundVisibility(.hidden, for: .windowToolbar)` for the System-Settings full-height look; the scene carries `.defaultSize(1000×680)` + `.windowResizability(.contentMinSize)` (a view `idealWidth` alone opened it at 900×608). ONE sidebar `List` whose rows switch with the level; '‹ Settings' + domain header ride in a top safe-area inset, Remove domain in a pinned one-row `List` (bottom inset) whose selection adapter never writes nil back. Verified in the `-HeraldUITest` harness #settings
- [gotcha] macOS 15+: tag List rows `.tag(route)`, NEVER `.tag(Optional(route))` for an Optional selection. `tag(_:includeOptional:)` already wraps, and an explicitly Optional tag matched nothing: rows ignored clicks and a programmatic selection drew no highlight (only `ForEach(id: \.self)` rows worked, via their implicit id tags). Cost a long spike chasing wrong causes (payload enums, list swaps, computed bindings — none mattered) #swiftui #list
- [decision] Route API: `AppEnvironment.settingsRoute: SettingsRoute` (`.general/.notifications/.privacy/.aiGateway/.account/.signatures/.domain(MailDomain.ID, DomainSettingsPage)`, pages overview/mailboxes/signatures/workflows/remove — see [[Herald AI Classification via Cloudflare AI Gateway]]) and `showSettings(_ route:, accountID:, open:)` — pass `{ openSettings() }` from `@Environment(\.openSettings)`; it switches account (if signed in), sets the route, THEN opens. The window draws `resolvedSettingsRoute`: an unknown/hidden domain → `.account`, no account → `.general`; the stored request is kept so a domain whose mailboxes load later still opens. `selectAccountFromSettings` drops a domain route to `.account`. The app menu's replaced `.appSettings` group now re-adds 'Settings…' ⌘, #settings #deeplink
- [decision] Account tint is OBSERVABLE through AppEnvironment: `accountTintName(for:)` / `accountTint(for:) -> MailTheme.AccountTint` / `hasAccountTintOverride(_:)` / `setAccountTint(_:for:)` (nil = Reset; names outside the 8 refused). Reads touch `accountTintRevision`, bumped by every write, so every avatar/badge repaints live — R4/R5 must read tints through these, never `account.<id>.tint` from UserDefaults directly (R6's `DomainBadgeResolver.resolve(mailboxID:mailboxes:accountID:in:)` reads the override from defaults and does NOT repaint; since R4 use the overload `resolve(mailboxID:mailboxes:accountID:tintName:in:)` with `accountTintName(for:)` and `domainPreferencesObserved()`). Sign-out: `requestSettingsSignOut` → dialog → `confirmSettingsSignOut(prompt)` acts only on the ARMED prompt id (a UUID) and signs out the account the prompt named; the dialog binding only drives presentation #tint #signout
- [convention] Reusable chrome in `Herald/Views/Settings/SettingsChrome.swift`: `SettingsPage(title:breadcrumb:scrolls:)` (serif `Typography.title`, 720 max, padding 4/40/32; `scrolls: false` for a self-scrolling Form, whose content then needs `.frame(minHeight: 0, maxHeight: .infinity)` or its min height overflows the window), `SettingsSection(title:)`, `SettingsCard` (lineSoft separators via `Group(subviews:)`), `SettingsRow(title:note:source:) { trailing }`, `SettingsSourceTag(.server/.herald)` (`Typography.sourceTag` mono 9 — renamed at the R5 merge; `Typography.tag` is now R5's Geist-10 "No mailbox" tag), `SettingsOutlineButtonStyle(isDestructive:)` (the Settings-local `SettingsDomainBadge` this originally listed folded into R6's `DomainBadge` in R8 and is gone). Breadcrumbs: 'Settings › Herald' / '› {account}' / '› {account} › {domain}'. Density = `GeneralSettingsPage.densityStorage(store:)` on `list.density` #settings #tokens

- [decision] The three real domain pages replace R7's `DomainSettingsPlaceholderPage` for `.overview`/`.mailboxes`/`.signatures`; `.remove` stays the placeholder for R9. `SettingsDetail`'s `.domain` case now routes through a `domainPage(_:item:accountID:breadcrumb:)` switch and wraps the result in `.id("\(domainID).\(page.rawValue)")` — `SettingsDetail`'s own switch keeps ONE structural identity across every `.domain` route (same `case`, different associated values), so without this id a page's local `@State` (the monogram field's draft) would survive a switch to a DIFFERENT domain instead of resetting #settings #swiftui
- [decision] Badge de-duplication landed: the Settings-local `SettingsDomainBadge` (SettingsChrome.swift) is gone, replaced by R6's shared `DomainBadge(monogram:tint:size:)` at `.sidebar` (18pt, the domains list row) and `.header` (24pt, a domain's own header) — both read the tint through `environment.accountTint(for:)`, never `UserDefaults` directly #tint
- [decision] Overview's monogram field (`DomainMonogramField`, private to SettingsDomainPages.swift) only writes through `updateDomainPreferences` when the trimmed value VALIDATES (`DomainMonogram.normalizeOverride`) or is empty (clears the override) — a mid-edit invalid keystroke is left alone rather than clearing a stored override, mirroring the rule `DomainPreferences.setMonogramOverride`'s own doc comment asks the caller to apply. The field's initial `@State` is seeded from a value the PARENT reads (where `@Environment` is available, unlike a view's `init`) and passed in as `storedOverride`, not from `item.monogram` (which is the auto-derived display value, not what the field itself holds) #domains #monogram
- [decision] `DomainNotifyEffective.effective(explicit:globalEnabled:)` (new, `Herald/Support/DomainNotifyEffective.swift`, pure/nonisolated) is the READ half of the tri-state notify preference for the Overview toggle: global OFF always wins (even over an explicit per-domain `true`), `nil` follows the global switch, an explicit value shows once global is on — the same rule `MailViewModel.notificationSilencedMailboxIDs()` enforces for actual banners, restated for what the toggle DRAWS. The toggle reads the global switch through `@AppStorage(NotificationSettings.newMailKey)` rather than a raw `UserDefaults` read through `domainPreferencesObserved()` — the global setting is written from a DIFFERENT page (Settings › Notifications) via its OWN `@AppStorage`, which is the one mechanism that repaints a view that did not make the write itself #notifications
- [decision] Mailboxes is read-only: `DomainMailboxesSettingsPage.rows(mailboxes:domain:)` (pure `static func`) filters the account's already-cached mailboxes to `domain.mailboxIDs` (never a fetch of its own) and reads each one's single primary address's `isPrimary`/`receiveEnabled`/`sendEnabled`/`displayName` straight from the API-shaped `MailboxAddress`; a domain member missing from the current `mailboxes` snapshot (a sync race) is skipped, not fabricated. Rendered in a `LazyVStack` (`DomainMailboxTable`), not `SettingsCard`'s eager `Group(subviews:)`, so an account with up to 100 mailboxes on one domain never lays out off-screen rows #mailboxes
- [decision] Signatures reuses `SignatureSettingsModel` verbatim: `DomainSignaturesSettingsPage` filters `model.groups` to `scope == .domain && scopeID == item.id` and its "New Signature" calls the model's new `beginCreate(preferring:)` (falls back to the first offered scope when the preferred one is not — yet — among `scopeOptions`). Extracted two pieces so the root Settings › Signatures pane and this page share them instead of forking: `View.signatureManagementModifiers(model:)` (the editor sheet, delete confirmation, VoiceOver announcement) and `SignatureStateMessagePane` (loading + the four load-failure screens — `.ready` is deliberately excluded, since what a page shows once loaded, and its own empty-state copy, is the caller's). The sidebar's domain signature count (`SettingsDomainRows.signatureCount`, R7) already reads the same cached model instance, so it stays in sync with no extra wiring #signatures
- [fact] Tests: `HeraldTests/DomainSettingsPagesTests.swift` (10) — the notify effective-value truth table, both Overview toggles' and the monogram field's write path through `updateDomainPreferences` (observable + reload), the mailbox table's filter/sort/primary/skip-missing-member logic, and domain-scoped signature creation (including the fallback case). - [decision] `hideDomain`/new `restoreDomain(_:accountID:)` (both `Herald/App/AppEnvironment+Domains.swift`) are the only writers of `DomainPreferences.setHidden`. `hideDomain` now also captures the domain's CURRENT name (`mail.domains.first{...}?.name`) and passes it as `setHidden`'s new `name:` param, stored under a new `hiddenName` key (same escaped-key scheme as `hidden`/`hiddenAt`, cleared together on restore) — the Hidden Domains list's fallback once a domain's mailboxes are gone from the account's cache; with no stored name either, the row falls back to the raw domain id rather than disappearing (fallback, never silent purge) #domains #preferences
- [decision] `HiddenDomainItem` (new, `Herald/App/SettingsRoute.swift`, beside `SettingsDomainItem`): `.hidden(mailboxes:accountID:defaults:)` builds the "HIDDEN DOMAINS" list from `DomainPreferences.hiddenDomainIDs`, newest-hide-first (ties by id). `AppEnvironment.hiddenDomains(accountID:)` is the read path. Settings needed NO extra navigation code for hiding the domain currently shown in Settings: `resolvedSettingsRoute` already falls back to `.account` on its own, since `settingsDomains(accountID:)` (what `SettingsRoute.resolved` checks) excludes hidden domains — R9 only locked this in with a test (`DomainRemoveSettingsPageTests.hidingCurrentSettingsDomainNavigatesAway`) #settings #navigation

- [decision] N5 admin link: `AppEnvironment.hqBaseAdminURL(for:)` (pure, static) rebuilds the URL from `account.origin`'s scheme/host/port only (never a stored path/query) and returns `nil` for anything but https; `openHQBaseAdmin(for:)` opens it via `NSWorkspace.shared.open` (never in-webview navigation, per "Herald Error Handling and Security Rules"). `SettingsCard` gained a `fill: Color = .surface` param (default unchanged everywhere else) so this page's server card can use the design's neutral `bg` fill instead of `surface`. New token `MailTheme.Wash.hiddenBadgeOpacity = 0.6` for the hidden list's dimmed `DomainBadge` #domains #security #tokens
- [fact] Tests: `HeraldTests/DomainRemoveSettingsPageTests.swift` (9) + 2 new in `DomainPreferencesTests.swift` (hiddenName round-trip, no stale write when hiding with no name) — restore reappearance, live-name vs stored-name vs raw-id fallback, newest-first ordering, the Settings-route auto-navigation lock-in, the all-domains-hidden reachability scenario, and the admin URL's https-only/origin-root rule. ## Update (2026-09-28 — F3: audit fixes)

- [decision] Menu-bar Sign Out (`MailCommands` app-menu group) no longer calls `environment.signOut(accountID:)` directly — it now routes through `showSettings(.account, accountID:) { openSettings() }` then `requestSettingsSignOut(accountID:)`, raising the SAME confirmation dialog Settings › Account's own "Sign Out…" does. `HeraldUITests/PageObjects/MailWindowPages.swift`'s `SidebarPage.signOut()` now also confirms that dialog (`app.sheets/dialogs.buttons["Sign Out"]`) after clicking the menu item; `SignInFailureTests.testASignOutThatCannotFinishRaisesAnAlertWithTheReason` is the one caller, unchanged itself since the page object absorbed the extra step #settings #signout
- [decision] `AppEnvironment.hqBaseAdminURL(for:)` (N5) rebuilds from `URLComponents(url: account.origin, resolvingAgainstBaseURL: false)` with path/query/fragment/user/password cleared, instead of re-assembling a fresh `URLComponents` from `.scheme`/`.host`/`.port` — `URLComponents.host` strips an IPv6 literal's `[...]` brackets, so the old shape silently produced no usable URL for one of those origins. The "Open in HQBase Admin" button is now `.disabled` (with `.help` text) when the URL is `nil` rather than a silent no-op #domains #security

- [decision] Stale route on Hide (a domain hidden while its own Remove-domain page — or any of its pages — was showing): `hideDomain` now rewrites the RAW `AppEnvironment.settingsRoute` to `.account` when it points inside the domain being hidden (previously only `resolvedSettingsRoute` moved away; the raw route was left standing on the hidden domain). `SettingsView`'s selection `Binding`'s setter now also compares the clicked route against the RAW `settingsRoute`, not `resolvedSettingsRoute` — comparing against the resolved value made a click on the already-highlighted Account row (once resolution had moved the highlight there) a no-op, so nothing ever moved the raw route and a later Restore jumped straight back to the hidden domain's page #settings #navigation
